# Engineering Constitution

## Purpose

Define project-specific engineering laws layered beneath the Aurelian kernel.

Do not invent facts. Add only rules grounded in observed code, team decisions, incidents, or recurring review feedback.

## Required Sections

### Project Laws

Short, durable rules that apply to all engineering work in this repo.

### Code Style And Patterns

Local conventions that are stronger than personal preference.

### Architecture Rules

Boundaries, dependency direction, module ownership, and forbidden shortcuts.

### Testing And Verification

Required checks by change type. Include commands and when to run them.

### Security And Data Handling

Secrets, PII, auth, authorization, logging, external calls, migrations, and destructive actions.

### Release And Operations

Deployment, rollback, monitoring, and incident constraints.

### Update Policy

Add rules only when they change future decisions. Delete stale rules when discovered.
