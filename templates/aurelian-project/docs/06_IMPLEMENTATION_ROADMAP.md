# Implementation Roadmap

## Purpose

Track reversible, evidence-gated milestones from current state to the desired project outcome.

Do not invent facts. Each milestone should cite the evidence or decision that justifies it.

## Required Sections

### Current Milestone

Objective, scope, owner/tool, risk, and done criteria.

### Milestone Queue

Ordered work items. Prefer risk retired and dependency order over apparent ease.

### Evidence Gates

What must be observed before moving to the next milestone?

### Verification Plan

Targeted checks, nearby checks, whole-project checks, visual checks, or review swarms required by risk.

### Blockers

User decisions, missing credentials, unknown facts, external dependencies, or irreversible checkpoints.

### Completed Milestones

Date, summary, evidence, residual risks, and links to reports.
